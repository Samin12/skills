# Editorial Playbook

Use this reference while selecting and composing visuals for a talking-head intro.

## Story model

An intro should alternate among three functions:

1. **Promise:** state what the viewer will learn or gain.
2. **Proof:** show a real output, action, comparison, or result.
3. **Orientation:** explain the path, levels, or stakes.

Lead with promise plus proof. Delay detailed orientation until the viewer has seen why the topic matters.

## Visual roles

Label each beat by its primary role:

- `result`: completed work, output montage, generated scene, finished website, or final artifact;
- `action`: a visible edit, transformation, scroll, build, or interaction;
- `comparison`: before/after, old/new, costly/efficient, or wrong/right;
- `evidence`: analytics, revenue, comments, asset counts, timeline length, or other substantiation;
- `map`: levels, steps, roadmap, or workflow;
- `reset`: full A-cam or a quiet hold that restores attention.

Consecutive beats should usually change role, source, scale, or motion language. Variety is functional: it prevents the viewer from mistaking repeated footage for new evidence.

## Claim-to-proof visual matrix

| Spoken claim pattern | Strong moving proof | Reject |
|---|---|---|
| N use cases or examples | N distinct micro-clips, one real use case each, with short context labels | One repeated UI shot or a static collage standing in for several claims |
| Sees or uses its own desktop/files | File-tree or folder selection → directory opens → cursor, file set, or result changes | Login screen, desktop wallpaper, or static file window |
| Works with tools or plugins | Plugin catalog scrolling for breadth; an in-tool state change for actual execution | Static logo grid used as proof that an action occurred |
| Builds a website | Live scroll, navigation, responsive behavior, or an animated page-state change | Held hero screenshot |
| Creates media or content | Generated output playing, revealing, changing slides, or opening into its finished form | Thumbnail grid or editor chrome with no output motion |
| Learns and repeats work | Captured workflow → saved routine → visible rerun or output | Static settings panel |
| Desktop-to-phone handoff | Job already underway; touch or input on the phone plus visible cursor, file, or state response | App launch, connecting, loading, black, or blank phone state |

Plugin scrolling proves access and breadth. It does not by itself prove execution; when the narration claims an action, prefer a visible state change inside the named tool.

## Rapid multi-use-case fan-out

- Match the advertised count: if the hook promises eight use cases, show eight distinct proof cards when footage exists.
- Fan cards out in narration order with roughly 150–250 ms staggering, then hold the completed map for roughly 0.8–1.2 seconds.
- Keep labels to one-to-four words and place them consistently. Labels identify proof; they do not add new claims.
- Let the presenter yield when a dense grid needs the frame. A four-by-two grid is a useful starting point for eight landscape clips.
- Start every micro-clip on motion or a decisive result. For the later deep dive, use a different moment from the same source when possible instead of replaying the exact hook slice.

When a sentence has two visual subclaims, switch proof at the spoken clause boundary: establish context first, then show the decisive action.

## Frame grammar

### A-cam PiP

- Anchor the presenter bottom-right by default.
- Protect the forehead, hands, microphone, and eye line.
- Keep one intentional border treatment. Crop away captured browser chrome or an existing outer card before adding a new frame.
- Move or hide the PiP when it covers the proof. Do not shrink the proof until it becomes unreadable.

### Full-screen proof

- Use for cinematic results, generated footage, large interfaces, and emotionally strong examples.
- Retain just enough UI context to make the source and action understandable.
- Prefer showing the outcome already in motion over the setup click that precedes it.

### Split comparison

- Keep both states simultaneously legible.
- Center the comparison in the available canvas and leave outer breathing room.
- Use a divider, matched scale, or synchronized timing to clarify what changed.
- Avoid unrelated presenter framing that competes with the comparison.

### Graphic or map

- Use when the narration names categories, levels, steps, or a causal relationship.
- Reveal one unit at a time in narration order.
- Keep on-screen copy shorter than the spoken explanation.

## Crop and zoom rules

- Begin wide enough to establish context, then push toward the relevant result.
- Keep the object of the sentence fully visible at the moment it is named.
- Do not crop out comparison partners, essential controls, product labels, faces, or the action's endpoint.
- If a frame looks impressive but the viewer cannot tell what changed, widen it.
- Avoid continuous zoom. Let motion settle before reading or judging a result.

## Source treatment

- Search the full user-authorized project, later scenes, asset folders, and permitted prior videos before settling for nearby filler.
- Qualify candidate motion with dense source frames or playback. Do not infer useful movement from one thumbnail or from timeline metadata alone.
- Trim away searching, hovering, loading, mis-clicks, and dead cursor travel.
- Preserve the decisive gesture, transformation, reveal, or completed state.
- Speed ramps may compress setup, but the proof should play at a readable speed.
- Use alternate moments from the same source when it genuinely demonstrates a different claim.
- Prefer live motion over a screenshot of the same moment.
- Reinspect the staged destination after every copy/trim/move. Correct source selection can still land on the wrong visual moment when Project-time and media-offset arithmetic is wrong.
- For stills, use one motivated operation: pan to detail, mask reveal, before/after wipe, annotation, or depth move.

## Pacing defaults

Treat these as starting points, not quotas:

- Hook proof: roughly 1–3 seconds per distinct result.
- Early explanation: roughly 3–6 seconds per visual world.
- Roadmap or comparison: hold long enough to read every item once.
- Reset: one short full A-cam or quiet composition after a rapid cluster.

Cut on meaning. A longer moving clip can outperform several decorative cuts.

## Anti-patterns

- Reusing the same clip several times in the opening without new information.
- Showing a click or hover instead of the action that follows.
- Over-zooming until the interface, comparison, or scene becomes ambiguous.
- Double-framing a presenter crop with an extra captured shell.
- Leaving a static screenshot on screen while the narration advances through several claims.
- Using a vertical source at unreadable scale without an intentional layout.
- Filling every gap with a generic slide instead of locating real proof.
- Letting labels, captions, and narration compete for attention.
- Copying third-party footage, voices, or faces from a style reference.
